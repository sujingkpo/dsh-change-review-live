## 二、条目 yml 全文

路径必须是 `data/plugins/sujingkpo__dsh-change-review-live.yml`——**文件名 = url 的 slug**（`slugFor()` 校验，写错 CI 直接红）。

```yaml
url: https://github.com/sujingkpo/dsh-change-review-live
name: sujingkpo/dsh-change-review-live
category: ui
description:
  en: "Live change review for DeepSeek Harness: tracks write/edit tool calls per session, lists changed files above the composer and opens each file's line-level diff in a plugin-registered right-sidebar tab, with session-log / initial-version / Git comparison modes, per-change and per-file revert, subagent aggregation and SSE updates. A fork of cirelir/dsh-change-review rebuilt around the right sidebar."
  zh: "实时审查插件：追踪会话内 write/edit 工具调用，改动列表常驻输入框上方，点开即在插件自注册的右侧栏标签页里查看行级 diff，支持「会话记录 / 初始版本 / Git 版本」三种对比、单项与整文件撤回、子代理聚合与 SSE 实时刷新，配色可自定义；fork 自 cirelir/dsh-change-review，审查界面整体重构到右侧栏。"
```

字段约束（`scripts/lib/entries.mjs` 的 `ENTRY_KEYS`）：只允许 `url` / `name` / `category` / `description.en|zh` / `tarball`；**多写一个键就会被打回**（比如 `npm:` 会被明确拒绝）。`category` 必须取自固定集合，`ui` 在集合内。描述含 `: ` 必须加引号（上面两条已用双引号包住），且必须单行。

### 第 2 步：往 fork 加条目并推分支

在你自己的终端（不要经过 DSH 沙箱）里整段粘贴：

```powershell
$dst = Join-Path $env:TEMP 'aw-list-submit'
if (Test-Path $dst) { Remove-Item -Recurse -Force $dst }
git clone --depth 1 git@github.com:sujingkpo/awesome-dsh-plugin.git $dst
Set-Location $dst
git checkout -b add-dsh-change-review-live

$yml = @'
url: https://github.com/sujingkpo/dsh-change-review-live
name: sujingkpo/dsh-change-review-live
category: ui
description:
  en: "Live change review for DeepSeek Harness: tracks write/edit tool calls per session, lists changed files above the composer and opens each file's line-level diff in a plugin-registered right-sidebar tab, with session-log / initial-version / Git comparison modes, per-change and per-file revert, subagent aggregation and SSE updates. A fork of cirelir/dsh-change-review rebuilt around the right sidebar."
  zh: "实时审查插件：追踪会话内 write/edit 工具调用，改动列表常驻输入框上方，点开即在插件自注册的右侧栏标签页里查看行级 diff，支持「会话记录 / 初始版本 / Git 版本」三种对比、单项与整文件撤回、子代理聚合与 SSE 实时刷新，配色可自定义；fork 自 cirelir/dsh-change-review，审查界面整体重构到右侧栏。"
'@
[IO.File]::WriteAllText("$dst\data\plugins\sujingkpo__dsh-change-review-live.yml", $yml, (New-Object System.Text.UTF8Encoding($false)))

git add data/plugins/sujingkpo__dsh-change-review-live.yml
git commit -m "Add sujingkpo/dsh-change-review-live"
git push -u origin add-dsh-change-review-live
Remove-Item -Recurse -Force $dst
```

> 用 `[IO.File]::WriteAllText` + `UTF8Encoding($false)` 是有意的：Windows PowerShell 5.1 的 `Set-Content -Encoding utf8` 会写 BOM，YAML 里的 BOM 属于自找麻烦；`utf8NoBOM` 参数只有 pwsh 7+ 有。这样写两个版本都安全。
> **只加这一个文件**：PR 只该动 `data/plugins/`（+1/-0）。手动改 README 或动别人的条目，正是维护者明确会追问的两件事。

## 四、对抗性审查：提交前必须知道的风险

1. **重复条目是唯一实质性风险。** 列表里已有 `cirelir/dsh-change-review`（category `git`，本插件的上游）和 `xwh5/dsh-change-review`（category `ui`，另一个 fork）。官方规则第 4 条：两个插件做同一件事时先来者保留位置，**但 fork 在「维护得更好」或「确实做了新东西」时会被收录**——被拒的真正原因是描述与代码不符，而不是「你 fork 了」。差异点是真实存在的：本插件把审查界面整体迁到右侧栏（插件自注册的 tab 类型）、新增输入框上方的审查列表、三种对比模式（会话记录 / 初始版本 / Git 版本）、单项与整文件撤回。所以描述末尾保留了 fork 说明，主动交代来源，避免维护者把它当成冒名条目。
2. **描述里的每句话都会被对着代码核。** 已逐条核对：右侧栏 tab = `sidebar.right.pane.tab` 席位 + `dsh-resource://diff-review/**`；三种对比 = `/diff-review/file` 的 ops/initial/git；撤回 = `/diff-review/revert`（单项三路行合并、整文件）；子代理聚合 = `resolveRootId`；SSE = `/diff-review/events`；配色 = 设置 → 实时审查（12 项）。**不要往描述里加数字或命令名**，夸大是明确说明的第一大退回原因。
3. **不要提交生成的 README。** 对方 CI 接受「只改 yml」，合并后在 main 上自动重新生成；手改 README 会撞上 `node scripts/generate-readme.mjs --check`。
4. **一个 PR 最多 3 条。** 只提这 1 条。
5. **`latest/download/` 式 tarball 会烂。** 本次不声明 `tarball`（仓库无构建步骤，源码安装即可用），不发 npm 也不影响收录——下载量只是市场展示项。
6. **沙箱事实（别再踩）**：本机 git 走 SSH 在 DSH 受限沙箱下必然失败（`couldn't create signal pipe, Win32 error 5`），走 HTTPS 失败于 `schannel: AcquireCredentialsHandle failed: SEC_E_NO_CREDENTIALS`；所以第 1、2 步必须在**沙箱外**的终端执行，或在 DSH 里单次提权到 `danger-full-access`（本次你选择自己推）。GitHub API 只读查询可以走代理 `http://10.0.8.34:10810` 用 `curl.exe` 完成，不需要提权。
