## 四、对抗性审查：提交前必须知道的风险

1. **重复条目是唯一实质性风险。** 列表里已有 `cirelir/dsh-change-review`（category `git`，本插件的上游）和 `xwh5/dsh-change-review`（category `ui`，另一个 fork）。官方规则第 4 条：两个插件做同一件事时先来者保留位置，**但 fork 在「维护得更好」或「确实做了新东西」时会被收录**——被拒的真正原因是描述与代码不符，而不是「你 fork 了」。差异点是真实存在的：本插件把审查界面整体迁到右侧栏（插件自注册的 tab 类型）、新增输入框上方的审查列表、三种对比模式（会话记录 / 初始版本 / Git 版本）、单项与整文件撤回。所以描述末尾保留了 fork 说明，主动交代来源，避免维护者把它当成冒名条目。
2. **描述里的每句话都会被对着代码核。** 已逐条核对：右侧栏 tab = `sidebar.right.pane.tab` 席位 + `dsh-resource://diff-review/**`；三种对比 = `/diff-review/file` 的 ops/initial/git；撤回 = `/diff-review/revert`（单项三路行合并、整文件）；子代理聚合 = `resolveRootId`；SSE = `/diff-review/events`；配色 = 设置 → 实时审查（12 项）。**不要往描述里加数字或命令名**，夸大是明确说明的第一大退回原因。
3. **不要提交生成的 README。** 对方 CI 接受「只改 yml」，合并后在 main 上自动重新生成；手改 README 会撞上 `node scripts/generate-readme.mjs --check`。
4. **一个 PR 最多 3 条。** 只提这 1 条。
5. **`latest/download/` 式 tarball 会烂。** 本次不声明 `tarball`（仓库无构建步骤，源码安装即可用），不发 npm 也不影响收录——下载量只是市场展示项。
6. **沙箱事实（别再踩）**：本机 git 走 SSH 在 DSH 受限沙箱下必然失败（`couldn't create signal pipe, Win32 error 5`），走 HTTPS 失败于 `schannel: AcquireCredentialsHandle failed: SEC_E_NO_CREDENTIALS`；所以第 2 步必须在**沙箱外**的终端执行，或在 DSH 里对该命令单次提权到 `danger-full-access`（本仓库第 1 步的 `git push` 就是这么推上去的：`b2a9ae3..bd83c04`）。GitHub API 只读查询可以走代理 `http://10.0.8.34:10810` 用 `curl.exe` 完成，不需要提权。

````markdown
Adds one entry file, as the contributing guide asks: `data/plugins/sujingkpo__dsh-change-review-live.yml` (category: `ui`). The generated READMEs are untouched — they regenerate on `main` after the merge.

**What it is.** A live change-review plugin for DSH. It records the before/after content of every `write` / `edit` tool call per session; the changed files are listed in a panel above the composer (status chip, path, turn badge, that turn's question, `+N/−N`, time), and clicking a row opens that file's diff in a right-sidebar tab type the plugin registers itself (`sidebar.right.pane.tab`, address `dsh-resource://diff-review/session/<sessionId>/<path>`). Per file you can compare **session log** (the operations recorded in this session), **initial version** (the file as it was before this session's first change) or **Git HEAD**; a single operation or the whole file can be reverted, with a confirmation before anything is written to disk. Subagent changes are aggregated up the owner chain to the root session, and the host broadcasts over SSE (plus a 15 s fallback poll), so the list and the diff tab refresh as files change. Twelve colors are configurable under **Settings → 实时审查**.

**Category.** `ui` — the review surface is the product (composer panel + sidebar diff tab); the host half exists to record the operations and serve the diffs.

**Relationship to the entries already listed.** This is a fork of `cirelir/dsh-change-review` (listed under `git`); `LICENSE` keeps the original `Copyright (c) 2026 cirelir`. The review UI was rebuilt rather than tweaked: the upstream review-view tab with its count badge, its per-turn change cards and its editor picker are gone, replaced by the composer-adjacent change list and the plugin-registered sidebar diff tab. A second fork, `xwh5/dsh-change-review`, is also listed under `ui`; its entry describes a diff2html side-by-side renderer, where this one renders the diff itself inside the sidebar tab type it registers.

**Requirements checklist**

- [x] `dsh.bundle` manifest — `package.json` declares `{ "bundle": { "patch": "./cordis.patch.yml" } }`, with `cordis.patch.yml` beside it inserting `id: diff-review`.

- [x] `dsh-plugin` topic added (along with `dsh-plugins`).
````
